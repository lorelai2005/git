# 仁维脚本生成系统

本仓库记录仁维短视频驾驶舱合作协议中**文本策划工作流**的实现与验收进度，并跟踪与之相连的剪辑、数据复盘交付。当前代码是 2026-10-03 从 193 服务器筛选的运行文件快照，依赖 Crabot、飞书通道、上游视频服务及服务器配置；**不能直接作为独立应用部署**。

## 项目范围

合同本期包含三个分别验收的模块：文本策划、自动化剪辑、两个指定账号的数据复盘。文本模块须走三轮完整流程，第三轮交付调研、账号定位与策划、分镜脚本、拍摄实施计划。剪辑模块须交付两个账号均可导入、编辑、保存并重开的剪映工程。复盘模块须对两个账号分别提供来源可追溯的数据和改进建议。详见 [交付范围](docs/contract-scope.md)。

## 当前状态

截至 2026-10-03，资料索引、事实与素材库、对标逻辑、脚本规则、视频声画证据和部分账号作品索引已有实现及测试。**三个合同模块均未在本仓库记录为最终验收通过**。尤其尚无可核验的两个账号剪映工程和双账号完整数据复盘证据。详见 [进度与缺口](docs/status-2026-10-03.md)。

## 使用方法（飞书端）

以下方法适用于已经部署并接入飞书的“仁维智能助手”。本仓库是运行文件快照，不能仅通过克隆仓库直接启动完整服务。

### 1. 开始任务

在飞书中打开“仁维智能助手”的聊天窗口，发送任务说明和相关资料。尽量一次说清楚四项信息：**为谁做、做什么、有什么资料、有哪些要求**。

首次任务可以参考：

```text
请帮我为【客户名称】的【账号名称】制作短视频脚本。
产品或服务：【填写】
目标人群：【填写】
本次目标：【引导咨询／到店／建立信任等】
拍摄条件：【例如1人、店内拍摄】
请根据我提供的资料，生成【数量】条、每条约【时长】秒的口播脚本。
缺少关键资料时先问我，不要编造。
```

### 2. 整理客户资料

先发送品牌介绍、产品资料、访谈记录或已有文案等附件，再说明资料所属的客户和账号：

```text
这些资料属于【客户名称】的【账号名称】。请整理客户文字素材库，标明信息来源和待核实内容。只使用本次资料，暂时不生成脚本。
```

### 3. 拆解对标视频

发送视频链接或视频文件，必要时补充字幕：

```text
请拆解这条视频：【链接或附件】。分析开头如何吸引注意、正文如何展开、结尾如何引导行动，并总结可借鉴的方法。没有读取到的内容请明确说明。
```

如需口播原文，请补充说明“先提供实际获取到的完整口播转写，再进行分析，不要用摘要代替全文”。链接能否读取、资料能否获取，以实际处理结果为准。

### 4. 复盘账号

账号复盘需要提供账号主页链接，并明确提出“账号复盘”；单条视频拆解不等于整个账号复盘。

```text
请复盘这个账号：【主页链接】。重点分析人设定位、内容变化和表现突出的作品，给出适合我借鉴的方向。请说明实际获取的作品范围，区分事实、推测和资料缺口。
```

### 5. 生成和修改脚本

资料整理完成后，可以直接要求生成脚本：

```text
请基于当前客户素材库和逻辑库，生成【数量】条约【时长】秒的短视频脚本。要求口语化、1人1场地能拍，每条包含标题、完整台词、画面建议和结尾引导。不要虚构销量、案例或人物经历。
```

修改时直接说明“改哪里、怎么改、哪些不动”，例如：

```text
第2条脚本太像广告。请减少口号，先讲一个具体困扰，再用已有产品事实回应。保留选题和结尾，只修改第2条，给我修改后的完整稿。
```

### 6. 切换客户或新任务

换客户、换账号时要明确说明，避免混用资料。如需隔离旧任务，在飞书私聊中单独发送：

```text
新建对话
```

收到确认后再发送新任务和资料。该操作用于开启不自动沿用旧聊天资料的新对话，不会删除旧消息或文件，也不等于取消旧任务。

### 7. 异常处理与结果核对

- 不知道任务进度时，要求助手列出已完成内容、正在执行的任务、卡点和下一步。
- 链接读取失败时，补充视频文件、字幕或截图。
- 采集中断时，要求沿用已保存结果继续，并说明限流后的可继续时间。
- 只收到服务器路径时，要求提供可打开的附件或下载入口；发送失败时先展示正文。
- 持续报错或没有回应时，保留原请求、报错内容和发生时间，联系维护人员，避免反复提交同一任务。
- 使用结果前核对客户和账号、事实与数据依据、拍摄条件，以及修改是否落实到完整正文。

助手提供的是创作辅助，不保证流量或成交；生成脚本也不等于自动发布。

## 仓库结构

- `runtime/skills/`：线上技能规则与素材准备脚本快照。
- `runtime/tools/`：受限来源索引、视频分析、时间轴和账号作品工具快照；另含爆款优先的断点续采工具 `collect-loop.sh` 与 `viral-pick.py`（见 [collect-loop-viral-pick](docs/collect-loop-viral-pick.md)）。
- `runtime/patches/`：模型适配器、重试和超时补丁快照。
- `docs/`：合同范围、进度、证据及排期。
- `templates/`：驻场问题与复验记录模板。

## 资料边界

原合同、客户附件、视频、账号数据、聊天记录、凭据、服务器配置和付款信息不上传。合同文件目前标注为草案，签章及附件一部分实施参数仍待双方确认。本仓库的状态记录不代替小鹿的书面验收。
