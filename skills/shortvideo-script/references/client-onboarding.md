# 首次入库：客户资料与目标确认

目标：**一轮问完，之后每次只要一句「写 N 条 X 主题」就能出片。**
问的时候不要发问卷，按下面四组顺序聊天问，边问边填 JSON。

---

## 一、定位（问 5 个问题）

1. 一句话说清你是做什么的、在哪、给谁做？（→ `one_liner`）
2. 别人为什么选你而不是隔壁？（→ `differentiators`，要能被镜头证明，不能是「服务好」）
3. 你不做什么？（→ `positioning`，把「不推销」「不办卡」这类承诺写进来）
4. 你的货/服务有哪几个清晰的风格或档位？（→ `style_tags`，命名要固定，别一会儿通勤风一会儿职场风）
5. 平时怎么跟客人说话？举一个你自己会说的句子。（→ `tone.voice`，后面所有口播都贴这个语气）

**判断标准**：`differentiators` 里每一条，你都能立刻想出一个镜头去证明它。
想不出来的，说明它只是话术，删掉。

## 二、客群（问 3 个问题）

1. 你的客人大致多大、是本地还是外地？（→ `audience.core`）
2. 他们来你这儿是为了完成什么事？（→ `audience.jobs`，「上班穿得体面」比「追求美」有用）
3. 他们在哪个平台、哪个商圈刷到你？（→ `audience.where`）

**判断标准**：`audience.core` 必须能写成「地域 + 年龄 + 身份」三段式，
写成「所有爱美的女性」就等于没写，同城内容会直接失效。

## 三、事实库 facts（这一组最费时间，但必须问完）

**规则：`status` 只有 `confirmed` 才能写进脚本。`pending` 的信息只能做字幕占位或干脆不提。**

逐条确认，每条都要问「这个数字确定吗？发布时还有效吗？」：

| key | 问什么 | 为什么要问 |
| --- | --- | --- |
| `address` | 门店具体位置，用「几号门 / 斜对面 / 几楼」描述 | 同城内容的命门，不能用「××米」 |
| `business_hours` | 营业时间 | 评论区必问，没确认就别写 |
| `opening_date` | 正式开业/活动日期 | 写错直接投诉 |
| `contact` | 电话还是微信？要不要留？ | 留错联系方式等于白拍 |
| `gift_quantity` | 赠品/名额的**真实区间** | 「50—100 份」要配「以现场为准」 |
| `claim_rule` | 领取条件、名额、期限 | 「人人有份」是广告法红线 |
| `price_*` | 价格带、是否打折 | 价格变动最频繁，宁可不说 |
| `founder_bg` | 主理人可公开的真实经历 | 人物故事的唯一素材来源，不允许编 |
| `activities` | 现场已经搭好的体验项目 | 没搭好的不许拍、不许说 |

数字类事实建议写成「区间 + 条件」：`"value": "果篮和伴手礼盒各 50—100 份", "caveat": "发布前需核对剩余数量与领取条件"`。

### 待确认项怎么写

还没问出来的写在 `pending`，并把「卡住了什么」写进 `blocks`：

```json
{"key": "opening_date", "question": "正式开业日期是哪天？", "blocks": ["口播报日期", "结尾字幕"]}
```

`validate.py` 会在出片时把这些提醒出来，避免忘了。

## 四、素材库 materials（问「能拍什么」，不问「想讲什么」）

对着这四个问题过一遍店里：

1. **场景**：站在店门口能拍到哪些画面？（门头、橱窗、主通道、试衣区、活动区…）
   → `scenes`，每条给一个 `shot_hint`（怎么拍才出效果）
2. **动作**：你和店员每天重复做哪些动作？（整理货、熨烫、搭配、打包…）
   → `actions`，动作比台词有说服力
3. **人物**：谁可以出镜？有没有授权？
   → `people`，`consent` 只有 `confirmed` 才能安排正脸镜头
4. **卖点段**：能被一条视频讲透的最小单位是什么？
   → `segments`，每条都要有 `proof`（现场怎么验证它真的存在）

**判断标准**：`segments[].proof` 写不出来的，就不是卖点，是形容词。

顺手把主理人说过的、可以原样用的句子记进 `voice_lines`——
这类原话是口播最好的素材，比文案写的更像人话。

## 五、确认脚本目标（策划案落地）

```bash
python scripts/new_client.py --id <client_id> --add-plan <goal_id> --plan-title "<任务名>"
```

填完 `plans/<goal_id>.json` 后，**用下面这段话跟客户确认，拿到明确点头再写**：

> 这次做 {count} 条，单条 {min}—{max} 秒，发 {platform}，
> 目标是 {goal.summary}。
> 每条都会出现的固定信息是：{must_mention}。
> 不会出现的是：{must_avoid}。
> 还有 {open_questions 条数} 项没确认（{列出}），这几项我先不写死，用字幕占位。
> 这样对吗？

客户改了什么，回填 JSON，不要只记在对话里——下次生成要用。

---

## 六、入库完成自检

```bash
python scripts/new_client.py --list
python scripts/retrieve.py material --client <id> --query "<本次主题关键词>"
```

`retrieve` 返回的 `usable` 列表如果凑不齐 5 条脚本的素材量（大约需要 15 个以上可用片段），
说明素材库还太薄，回头继续问「能拍什么」，不要靠编。
