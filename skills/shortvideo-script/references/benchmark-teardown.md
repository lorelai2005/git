# 对标视频拆解

对标视频的价值在**结构**，不在文案。
拆解的目标是产出一张能直接喂给写稿的卡：这条片子为什么能留住人、每一步在干什么、我们能搬哪一层。

模板：`templates/benchmark.template.json`
存放：

- 客户自己的对标 → `knowledge/clients/<id>/benchmarks/<benchmark_id>.json`
- 跨客户可复用的 → `knowledge/benchmarks/<benchmark_id>.json`

```bash
python scripts/new_client.py --id <client_id> --add-benchmark [BENCHMARK_ID]
```

---

## 拆什么（按顺序填，别跳）

### 1. `source` — 来源与数据

平台、链接、作者、发布时间、时长，以及抓取那一刻的点赞/评论/转发。
**数据只做筛选依据，不做结论依据**：一条 10 万赞的片子，可能只是投流砸出来的。

### 2. `why_pick` — 为什么选它当对标

必须写清属于哪一种：

- **结构像**：它的推进方式和我们的目标匹配（最有用）
- **人群重合**：刷它的人就是我们要的人
- **数据好**：完播/互动显著高于该账号均值
- **形式新**：新机位、新呈现，但结构仍可拆

只写「因为它火」的，等于没拆。

### 3. `hook` — 前 3 秒

分三栏记，缺一栏就不完整：

| 字段 | 记什么 | 例子 |
| --- | --- | --- |
| `first_3s_visual` | 第一帧画面 | 镜头怼着门头，一只手推开门 |
| `first_3s_audio` | 第一句话 | 「这家店我找了三次才找到。」 |
| `hook_type` | 属于哪类钩子 | 结果前置 / 提问 / 反差 / 痛点动作 / 价格锚点 |
| `retention_devices` | 3 秒内给了什么理由让人不划走 | 「给了地标」+「给了悬念：找了三次」 |

`retention_devices` 是全篇最重要的一栏。说不出理由的，说明它的钩子靠的是账号权重而不是结构，
**不要拿来当模板**。

### 4. `beats` — 逐段

按 5—8 秒切一段，每段三个字段：

```json
{"t": "3—18秒", "what": "画面发生了什么", "why": "为什么这么排", "switch": "换成我们的场景该怎么拍"}
```

`switch` 是从「看懂」到「能用」的那一步。如果某段写不出 `switch`，
说明这段依赖该账号的人设或素材，搬不动，标注进 `not_reusable`。

### 5. `logic_id` — 归到哪张逻辑卡

对得上已有卡就填卡 id；连续两条以上都对不上，说明库里缺一种结构，
去 `knowledge/viral-logic/library.json` 新增一张卡（字段见 `references/viral-logic.md`）。

### 6. `reusable` / `not_reusable` — 边界

这一段最容易偷懒，但最影响后续：

- `reusable`：结构、节奏、机位、字幕位置、段落时长配比
- `not_reusable`：人设、口头禅、具体数据、他人素材、依赖特定身份的梗、
  需要特殊场地/设备的镜头

**判断标准**：`not_reusable` 里写的东西，如果出现在我们的脚本里，会不会像抄的？
会，就必须写进来。

## 拆解质量自检

拆完之后用这三个问题验一下：

1. 把 `beats` 按顺序念出来，能不能复述这条片子的推进逻辑？（不能 → 切得太粗）
2. 只看 `switch` 一列，别人能不能照着拍？（不能 → 写太虚）
3. `not_reusable` 至少 2 条？（少于 2 条 → 大概率没认真找边界）

## 常见拆错

| 错误 | 后果 | 正确做法 |
| --- | --- | --- |
| 把文案抄下来当剧本 | 平台判搬运，且人设不匹配 | 只记 `what/why`，不记原句 |
| 按镜头个数切段，不按信息切 | 结构无法复用 | 一段≤一个信息点 |
| 忽略前 3 秒 | 后面全白拆 | `hook` 三栏必须齐 |
| 把投流效果归因为结构 | 复刻失败 | 看互动率，不看绝对播放量 |
| `switch` 写成「同理可得」 | 等于没写 | 写到具体机位和动作 |
