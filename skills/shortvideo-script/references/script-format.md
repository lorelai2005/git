# 版式规范（对齐参考稿）

参考稿：`assets/reference-sample.pdf`（《淑情哲依开业庆典 5 条短视频脚本》，A4，6 页）。
下面所有数值都是从该 PDF 逐像素量出来的，`scripts/build_docx.py` 里的常量与之一一对应。
改版式时**先改这份文档，再改代码**，否则两边会漂。

| 项 | 值 |
| --- | --- |
| 纸张 | A4 纵向 210 × 297 mm |
| 左右页边距 | 31.7 mm（= 3.17 cm，Word 默认 1.25"） |
| 上边距 | 26 mm |
| 下边距 | 22 mm |
| 正文宽度 | 146.6 mm |
| 中文字体 | 微软雅黑（`Microsoft YaHei` / `微软雅黑`），西文同族 |

## 字号与颜色

| 元素 | 字号 | 字重 | 颜色 |
| --- | --- | --- | --- |
| 主标题 | 21 pt | Bold | `#0B5394` 深蓝，居中 |
| 主标题下横线 | 1.25 pt | — | `#0B5394`，通栏 |
| 元信息行（适用平台等） | 10 pt | Regular | `#333333` |
| 脚本标题（`01 | …`） | 10.5 pt | Regular | `#333333` |
| 正文 / 口播 | 10 pt | Regular | `#333333` |
| 栏目小标题 | 12.5 pt | Bold | `#C65911` 橙 |
| 栏目竖条 | 3 pt 宽 | — | `#C65911`，高 12 mm，探入左侧页边距 |
| 表头文字 | 10.5 pt | Bold | `#FFFFFF` |
| 表头底色 | — | — | `#C65911` |
| 表体文字 | 10 pt | Regular | `#333333` |
| 表格线 | 0.5 pt | — | `#BFBFBF` |

主标题居中会让它看起来几乎贴着左右边界（大写标题约 141 mm 宽），这是参考稿的样子，不要改成左对齐。

## 间距

| 项 | 值 |
| --- | --- |
| 主标题行距 | 固定值 30 pt，下边框间距 12 pt |
| 正文行距 | 固定值 17 pt |
| 段后距 | 4.5 pt |
| 小标题行距 | 固定值 32 pt（把橙色竖条撑到 12 mm 高） |
| 小标题段前 / 段后 | 4 pt / 2 pt |
| 表头行最小高度 | 12.7 mm，垂直居中 |
| 单元格内边距 | 上下 3.5 pt，左右 5.5 pt |

小标题的竖条是用段落左边框实现的：`space=10` 让它探出到页边距里，行距撑到 32 pt 才有 12 mm 高。
改行距会直接改变竖条高度，这是参考稿最容易被忽略的一处。

## 拍摄执行表

四列，固定列宽（不可自适应，否则长文案会把「时间」列挤宽）：

| 列 | 内容 | 宽度占比 | 约合 |
| --- | --- | --- | --- |
| 1 | 时间 | 8.35 % | 12.2 mm |
| 2 | 具体视频画面 | 29.34 % | 43.0 mm |
| 3 | 口播/同期声 | 31.24 % | 45.8 mm |
| 4 | 执行要点 | 31.06 % | 45.5 mm |

- 第一列很窄，`0—3秒` 会折成两行（`0—3` / `秒`），参考稿就是这样，属于正常现象。
- 行内**不允许跨页拆分**（`cantSplit`）；整表可以跨页，跨页时不重复表头（与参考稿一致）。
- 表格左边缘与正文左对齐，右边缘与正文右对齐。

## 每条脚本的固定骨架

顺序不能变：

```
{序号} | {脚本标题}
内容结构     A → B → C → D → E
开头钩子     一句话
完整口播     3—5 个自然段，一段一个意思
拍摄执行     4 列表格，4—6 行
发布标签     #品牌 #品类 #地标 …（≥3 个）
```

全部脚本之后：

```
统一发布前核对（标题可改，如「五条脚本统一发布前核对」）
1. …
2. …
```

## 视觉红线

- 不要给正文加粗、加下划线、加底色来「突出重点」——参考稿靠小标题和空行分段
- 不要在表格里放 emoji 或符号列表
- 主标题保持一行；标题超过约 22 个全角字符时缩小字号或缩短措辞，不要折行
- 口播段落之间不要加空行（靠段后距 4.5 pt 自然分开），否则整篇会虚涨两页
