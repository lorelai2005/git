# 指标口径与诊断规则字典

> 这个文件是**唯一的计算口径声明**。`facts.py` 按这里算，报告按这里解释，模型不允许另立口径。
> 阈值是配置项（`review.thresholds`），改阈值只改配置。

---

## 一、口径定义

### 1. 累计值 vs 窗口增量（最容易搞错的一条）

抖音的 `play_count` / `like_count` 是**作品发布至今的累计值**，不是日增。
所以「本期播放」不是把每天的播放加起来，而是：

```
某作品窗口增量 = 窗口内最后一次快照 − 窗口开始前最后一次快照
窗口播放 = Σ 所有作品的窗口增量
```

窗口内新发的作品（窗口前没有快照）按**全量**计入（它本来就只在这段时间产生播放）。

实现：`repo.video_window_growth()`，单条 SQL 用相关子查询取「窗口前最后一次快照」，
避免把整条时间序列搬到 Python 里做（大号几千条作品会拖死进程）。

### 2. 各项指标

| 指标 | 公式 | 说明 |
| --- | --- | --- |
| 播放量 | Σ 作品 `play_count` 窗口增量 | 主指标 |
| 互动量 | 点赞 + 评论 + 转发 + 收藏 窗口增量 | 不含播放 |
| 互动率 | 互动量 ÷ 播放量 | 加权口径，不是各作品互动率的平均 |
| 完播率 | Σ(作品完播率 × 作品播放) ÷ Σ(作品播放) | **按播放量加权**；直接平均会被小播放作品带偏 |
| 2 秒跳出率 | 同上加权 | 只反映开头 3 秒吸引力 |
| 收藏率 | 收藏增量 ÷ 播放增量 | 衡量“内容有用度”，比点赞更硬 |
| 粉丝净增 | 期末粉丝 − 期初粉丝 | 与「新增粉丝 − 取关」互相对账 |
| 涨粉转化 | 粉丝净增 ÷ 播放 | 衡量“看完愿不愿意关注” |
| 单条平均播放 | 窗口播放 ÷ 作品数（窗口内有增量的作品） | 衡量内容稳定产出能力 |
| TOP1 播放占比 | 最高播放作品的窗口播放 ÷ 窗口播放 | >50% 说明吃单条爆款 |
| 新内容播放占比 | 本期内新发作品的播放 ÷ 窗口播放 | 衡量增量来自新内容还是老长尾 |
| 断更天数 | 今天 − 最近一条作品发布日 | 无作品时为 `None` |

### 3. 数据质量前置判断

复盘前先看 `dy.v_data_freshness`：

| 情况 | facts 里的表现 | 报告要求 |
| --- | --- | --- |
| 最新快照距今 ≥3 天 | `data_gaps` 含“最新指标快照距今 N 天” + `DATA_STALE` | 必须提示“结论可能滞后”，不得给出精确趋势判断 |
| 完全无快照 | 抛 `DATA_UNAVAILABLE`，不生成报告 | 先补采 |
| 缺粉丝画像 | `data_gaps` 含“缺少粉丝画像数据” | 人像相关结论写“暂无数据” |
| 缺封面点击率 | `data_gaps` 含“缺少封面点击率” | 不提封面优化建议 |

## 二、阈值分层（默认值，可在 `review.thresholds` 覆盖）

| 指标 | 健康线 | 警戒线 | 配置键 |
| --- | --- | --- | --- |
| 完播率 | ≥ 25% | < 15% | `finish_rate_good` / `finish_rate_warn` |
| 互动率 | ≥ 5% | < 2% | `interaction_rate_good` / `interaction_rate_warn` |
| 播放环比 | ≥ -30% | < -30% | `play_drop_warn` |
| 粉丝净增 | > 0 | ≤ 0 | `follower_growth_warn` |
| 断更天数 | < 7 天 | ≥ 7 天 | `publish_gap_days_warn` |
| 新内容播放占比 | ≥ 30% | < 30% | `low_new_video_ratio_warn` |

> 这些数字是**代运营家居/本地生活类客户的起始参考值**，不是平台标准。
> 新客户接入第一个月后，用客户自己的历史最好成绩校准（改配置即可，不改代码）。

## 三、诊断规则清单

规则在 `facts._diagnose()` 里，确定性输出。**模型只能解释、排序、补充动作，不能新增规则。**

| code | 级别 | 触发条件 | 建议方向（模型可润色，不可改意） |
| --- | --- | --- | --- |
| `DATA_STALE` | critical | 最新快照距今 ≥3 天，或无任何快照/作品数据 | 先修采集链路，再谈优化 |
| `PLAY_DROP` | critical | 播放环比 ≤ `play_drop_warn`（默认 -30%） | 排查选题与开头 3 秒；复用上期最强钩子；暂停同期同类内容 |
| `FINISH_RATE_LOW` | warn | 加权完播率 < `finish_rate_warn`（15%） | 核心结论前置到 3 秒内；时长压到 15–30s；砍结尾自述 |
| `FINISH_RATE_MID` | info | `finish_rate_warn` ≤ 完播率 < `finish_rate_good` | 做开头 A/B 测试（只换前 3 秒） |
| `INTERACTION_LOW` | warn | 加权互动率 < `interaction_rate_warn`（2%） | 埋可代入提问/可反驳观点；评论区高赞做下一条；结尾引导收藏 |
| `INTERACTION_GOOD` | info | 互动率 ≥ `interaction_rate_good`（5%） | 把该形式固化成模板批量复制 |
| `FOLLOWER_STALL` | warn | 粉丝净增 ≤ `follower_growth_warn`（0） | 强化账号身份（关注能得到什么）；排查定位偏移导致取关 |
| `PUBLISH_GAP` | warn | 断更天数 ≥ `publish_gap_days_warn`（7） | 恢复稳定更新（建议每周≥3 条）；先用库存补位 |
| `CONCENTRATION_RISK` | warn | TOP1 播放占比 ≥50% 且窗口内 ≥3 条有播放的作品 | 把爆款结构拆成公式（同钩子换场景/人群），3–5 条验证可复制性 |
| `OLD_CONTENT_DRIVEN` | info | 新内容播放占比 < 30% | 老作品有长尾是资产；把评论区需求整理成新选题清单 |
| `NO_NEW_PUBLISH` | warn | 本期发布 0 条但仍有播放 | 排期发库存；复用上期最优结构；长期停更会掉流量池等级 |
| `NO_AUDIENCE_DATA` | info | 无粉丝画像 | 补授权画像权限，或人工归纳人群后校准选题 |
| `HEALTHY` | info | 以上全部未触发 | 维持节奏，把本期最好的 2–3 条结构整理成模板 |

排序：`critical` → `warn` → `info`（`facts.py` 里固定，报告不得打乱严重度顺序）。

## 四、报告里禁止出现的表述

| 禁止 | 原因 | 替换写法 |
| --- | --- | --- |
| “行业平均完播率约 30%” | 没有数据来源，属于编造 | “完播率 18.8%，低于健康线 25%” |
| “抖音算法最近调整了” | 无法验证 | 不写，或写“需结合账号近期内容变化判断” |
| “预计下个周期能涨到 10 万播放” | 无依据的预测 | “按当前结构复用，目标是把单条播放稳定在 X 以上” |
| “建议提升内容质量” | 不可执行 | “第 3 秒直接给结论，砍掉前 2 秒寒暄” |
| 直接写客户账号 open_id | 无意义且涉及标识 | 用账号名/抖音号 |
