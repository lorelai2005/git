# 账号复盘文档与前端交付

## 调用口令

~~~text
给我最近{客户名称或账号ID}的账号数据
~~~

例如“给我最近淑情哲依的账号数据”或“给我最近82713045072的账号数据”。账号由授权映射解析，不固定使用示例账号。“最近”默认最近三个自然月；用户明确给出周期时采用用户指定的周期。

这是完整复盘文档请求，不需要用户再补一句“加上提升方案”。同一次请求输出一份同时含数据复盘和提升方案的文档，默认返回请求发生的前端会话。普通查询不要求用户再提供另一个飞书收件人。

## 文档格式与内容

默认格式为DOCX。若前端已有可用的在线文档组件，允许返回一份用户可访问的在线文档。文件名使用“{客户名称}_{账号ID}_账号数据复盘与提升方案_{日期}.docx”。

| 部分 | 必须包含 |
| --- | --- |
| 账号与数据范围 | 客户名称、平台账号ID、申请周期、实际有数据的日期范围、采集时间和报告生成时间 |
| 核心数据表 | 投稿、播放、互动、观看和粉丝等已取得指标；区分日发生量、期末存量、周期比例和作品累计值 |
| 作品表现 | 可取得的作品数据对比、代表作品和问题作品；不能把详情不可读的作品当成零表现 |
| 复盘发现 | 每条结论对应具体数据证据，区分已确认现象与可能原因；没有依据不写行业均值或因果结论 |
| 数据提升方案 | 按问题提出具体动作和验证方法，避免泛泛写“优化内容”“提高质量” |
| 缺失与边界 | 未返回日期、缺失字段、未覆盖后台模块，以及这些缺口对结论的影响 |

提升方案采用可执行的行动表：

| 字段 | 写法 |
| --- | --- |
| 问题与依据 | 具体表现及对应数据，不凭空补数字 |
| 优先级 | 根据影响与证据强弱给出建议，说明理由 |
| 动作 | 明确改动什么、怎么做，不代替客户实际执行 |
| 数量或频率 | 写成建议实验计划，不写成已有事实 |
| 负责人 | 已知则填写；未知写“待指定”，不编造姓名 |
| 观察指标 | 能被现有采集链路验证的指标；不可取得时说明需要补充数据 |
| 预期方向 | 标注为建议目标或待验证假设，不保证增长幅度 |
| 复盘时间 | 根据报告日期和采集节奏给出具体建议日期，不能伪称已创建提醒 |

不要求每次都生成相同页数或凑满所有指标。数据不足时仍可整理已有事实与补数据建议，但必须在文档前部说明覆盖不足；若完全没有数据，先说明未完成接入或采集，不生成虚假的复盘。

## 生成与校验

1. 使用已解析账号的MCP结果形成数据事实，按next_offset读取所需页。记录统计周期和来源，不跨客户混合。
2. 对用户要求的周期使用对应数据。若只能取得三个月汇总而用户要求7天，不能直接改报告标题冒充7天结果。
3. 用当前运行环境可用的文档生成工具制作成品。三个douyin_account_*工具只读数据，不负责生成DOCX，不能向它们发送未定义的文档参数。
4. 确认文件真实存在、能打开或渲染，检查标题、账号ID、周期、表格、缺失说明和数据提升方案。不能把Excel或Markdown仅改后缀为docx。
5. 将文档中的数字与读库事实或可复算结果核对；周期比例不从日比例简单取平均，未知字段不补0。

## 前端返回

通过实际可用的附件上传或在线文档工具交付到请求会话。验收应同时满足：

- 文档已生成，且包含数据复盘与提升方案两个部分。
- 上传或文档创建操作返回真实文件标识、附件回执或文档链接。
- 请求用户具有访问权限，前端确实呈现可打开的附件或链接。

前端的成功回复应简洁，例如：“已生成《淑情哲依账号数据复盘与提升方案》，请查看文档。统计周期及数据缺口已在文档中注明。”实际文档附件或链接必须同时返回。

只有服务器文件路径、聊天文字或一张原始Excel表时，不算本流程的文档交付成功。生成成功但上传失败，应说明文档已生成、前端交付未完成；没有文档工具，应明确说明尚缺该能力，不编造文件或下载链接。

## 当前实现边界

本次修改的是本地Skill口令和交付要求，不自动部署前端。现有MCP提供账号状态、作品及按日数据查询，采集器提供Excel；旧OAuth CLI的飞书模块输出文字或卡片。这些能力不能当作DOCX生成与前端附件交付已完成的证据。

发布该Skill时，需把文档生成和前端交付组件连接到上述流程，再用实际请求验证。跨客户查询同样需要相应客户的授权、数据库账号映射和工具绑定，不能仅改口令就宣称所有客户均已接入。
