# 抖音账号数据复盘 Skill

当前入口：[SKILL.md](SKILL.md)。版本2.1使用统一口令，并复用已部署的浏览器采集和 PostgreSQL 链路：

~~~text
本机专用 Chrome 保存登录态
  → 每三天13:00采集最近三个自然月
  → 原始数据与Excel
  → 自动写入 renwei_script.review
  → Crabot MCP读库、生成账号数据复盘与数据提升方案文档
  → 返回请求前端的文档附件或可访问文档链接
~~~

“长期登录”表示持久化登录态复用，不保证永久免扫码；失效后由客户在本机恢复。浏览器目录和Cookie不上传服务器。当前实例仅绑定淑情哲依（82713045072），新账号需要独立接入。

使用 [浏览器与 PostgreSQL 接入说明](references/browser-postgres-workflow.md) 查找现有采集目录、手动补采入口、数据库表、MCP参数与故障判断。缺失字段和日期保留为NULL，不补成零；申请三个月不代表后台实际提供完整历史。

[manifest.yaml](manifest.yaml) 已改为当前组件的运行映射说明，不是自动部署脚本。实际Crabot工具注册仍由服务器管理；本次本地Skill更新不代表已安装或发布到Crabot。默认将文档返回请求会话；转发到其他位置时使用已指定的收件位置，并验证交付结果。


## 使用口令

~~~text
给我最近淑情哲依的账号数据
~~~

也可以填写账号ID：“给我最近82713045072的账号数据”。后续客户使用相同格式，先匹配其授权账号和接入绑定；未接入的客户不会被替换成示例账号。

该口令默认要求最近三个自然月的一份完整文档，包含账号数据复盘、数据依据、提升行动方案和数据缺口说明。默认DOCX；已有可用在线文档组件时也可返回在线文档。Excel只是可选附表，不代替复盘文档。详见 [复盘文档交付要求](references/review-document-delivery.md)。

目前完成的是本地Skill规则修改。现有MCP只负责读库，文档生成和前端附件交付需要接入对应工具并完成发布验收；不能据此认为线上新口令和文档返回已经生效。

## 旧OAuth实现

目录中的 `src/dyreview`、`config`、`deploy`、`.env.example`、原有测试、旧部署清单及旧参考文档仍是OAuth版本资料。其 `dyreview collect/token/init-db` 等命令不用于当前流程，不应照旧部署清单建立token续期或服务器重复采集任务。

此次修改的是Skill指令及接入说明，复用外部已部署组件；没有把旧Python CLI改写成浏览器采集器。旧CLI的数字校验、报告去重、Token用量入库和飞书推送也未自动迁移到当前MCP，不能用旧demo验证来证明新链路已完成这些功能。
